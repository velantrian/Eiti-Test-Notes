# Полный отчёт: аудит офлайн-движка EITI в PR #59

**Статус PR:** открыт, Draft, не смёржен. Этот пакет добавляет исследовательские материалы и тестовые фикстуры; runtime приложения не менялся. Целевая ветка — только `velantrian/Eiti-Test-Notes`.

## Краткий результат

В PR добавлены 130 синтетических одноходовых формулировок, 7 контекстных диалогов и воспроизводимый baseline текущего `EitiFrames`. На пустом состоянии парсер вернул метку для 86 фраз и `null` для 44. Это наблюдаемые выходы на текущем корпусе, а не оценка accuracy: целевые `expect.intent` — смысловые метки для аудита, они не обязаны совпадать с ID, которые движок уже реализует.

Также добавлены исследовательский обзор с 36 источниками и архитектурный эскиз: он описывает фактическое состояние локальной KB и отделяет предлагаемые изменения от работающего кода. Число карточек понятий сверено как **545, не 572**.

## Что не реализовано и что остаётся неизвестным

- В приложении не менялись `index.html`, `local/`, `kb/`, Service Worker, манифест и версия 14.14.0. Это пакет для аудита и планирования, не готовая реализация офлайн-архитектуры.
- P0–P3 в исследовании — рекомендации. Нет калибровки confidence на отложенном наборе, измерения ложных уверенных ответов или полноценного offline E2E для незагруженных пакетов, хеш-ошибок и сохранения старого кеша.
- Все фразы и диалоги синтетические. Их частотность в реальных чатах не установлена; 86/44 — не accuracy, precision или pass rate. Семь диалогов прошли проверку структуры, но отдельный тестовый прогон через stateful-логику движка ещё нужен.
- Полный `offline-survey-01.md` и исходный анализ пропусков по настроениям отсутствовали. Счётчики из брифа (54 intent, 40 семейств, 1 484 варианта триггеров и 47 кризисных фраз) указаны как проектные данные, а не независимая оценка качества или языковой частотности.
- Не найден сопоставимый лицензированный современный корпус русских чат-интентов; частоты сленга и эмодзи, русские WER для Chrome Web Speech API и клиническая валидация не установлены. Перед использованием внешних корпусов нужна проверка лицензии каждого компонента.
- Телефоны кризисной поддержки и экстренные номера проверены по официальным страницам Германии/ЕС в исследовательском отчёте, но в приложение не добавлялись. Их нужно перепроверять перед релизом и показывать только при подтверждённой локали; предложения P0 требуют отдельной клинической/экспертной проверки.
- Любое будущее расширение метаданных карточек, предзагрузка 545 карточек, новые сообщения об офлайн-пробелах и confidence-пороги требуют отдельной реализации и регрессионных тестов.

**Решение:** оставить PR #59 в Draft для аудита владельцем. Этот отчёт не рекомендует сливать его как реализацию новых runtime-функций.
